## Agent 执行链路 Trace 可视化（方案设计阶段）

- 需求明确为运行时 Trace：谁调用了谁、每步耗时、哪步失败、每步 token。不含编排画布、不含结果图表。
- 产出方案文档 `docs/AGENT_TRACE_PLAN.md`（选型、数据模型、降噪算法、改动清单、验证方案、风险兜底）。
- 技术选型结论：走 LangChain `AsyncCallbackHandler` 挂 `config["callbacks"]`，而不是在 `astream` 循环里手工埋点——LangChain 的 run_id/parent_run_id 本身就是树，只需做降噪+补时间+补 token。
- 关键设计：
  - 三段式压实：全量记录 → 保留判定 → 噪音层删除后父子重挂到最近保留祖先
  - 判重用 `(agent, node)` 而非单 node（主图/子图节点名都叫 agent/tools，只看 node 会丢子图链路）
  - agent 归属从 `metadata["langgraph_checkpoint_ns"]` 取 `:` 前一段
  - token 四路 fallback（usage_metadata / llm_output.token_usage / response_metadata / 记 0 并计 missing_usage）
  - 两种 token 口径：span 自身 tokens、含后代的 subtree_tokens（节点展示用后者）
  - 中断时未闭合 span 标 interrupted 并补 end_ms，让甘特能画出"卡在审批"那段
- 已建 `src/agent/trace/models.py`（Span 模型，零框架依赖，便于单测）。
- 环境情况：本机无 venv，langchain/langgraph 依赖全在 Docker 里，无法端到端跑；验证靠 py_compile + 对 collector 的纯逻辑 mock 单测 + 前端 tsc/next build。
- 待实施（等用户确认）：collector.py → handler.py → chat.py 接入/落库/API → 前端 TracePanel。
